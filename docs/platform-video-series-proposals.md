# Computer Agents Video Series Proposals

This document proposes a practical video content program for showing the platform, teaching users how to work with it, and demonstrating real use cases. The goal is to build a library that works for onboarding, sales, support, developer education, and product-led growth.

## Core Narrative

Computer Agents is not just a chat UI. It is a workspace where users can:

- create and run agent threads,
- work with files, images, videos, spreadsheets, documents, and code,
- organize work in projects, tasks, boards, and scheduled runs,
- configure agents, computers, skills, plugins, and models,
- build and deploy web apps, functions, databases, auth, secrets, and payments,
- generate creative assets with image and video models,
- monitor cost, usage, logs, files, and outputs.

The strongest video strategy is to show complete workflows where an agent creates or changes something real: a file, a report, an image, a video, a project plan, a deployed app, a database, or a scheduled automation.

## Audience Tracks

### New Users

Goal: understand what the product is and complete the first useful run.

Best formats:

- 2-4 minute quickstarts.
- 30-60 second feature teasers.
- "Before and after" demos.

### Operators and Teams

Goal: show how teams can manage work, projects, recurring tasks, documents, and production outputs.

Best formats:

- Workflow walkthroughs.
- Use case playbooks.
- Project lifecycle demos.

### Builders and Developers

Goal: show that agents can build, deploy, inspect, and debug real software resources.

Best formats:

- Build-along videos.
- Debugging sessions.
- API and deployment walkthroughs.

### Creative and Marketing Users

Goal: show Imagine as a production environment for campaign assets, images, videos, pitch decks, and templates.

Best formats:

- Template-to-output demos.
- Iterative editing workflows.
- Short creative campaigns.

### Power Users and Admins

Goal: show configuration, model choice, budget control, skill defaults, usage analytics, and integrations.

Best formats:

- Admin walkthroughs.
- Cost and model explainers.
- Governance and configuration demos.

## Recommended Series Map

### Series 1: Start Here

Purpose: fastest path from zero to value.

1. Welcome to Computer Agents
   - Goal: explain the platform in one cohesive tour.
   - Demo flow: Create home -> task input -> thread screen -> files -> projects -> configure -> develop -> imagine.
   - Key proof points: the same workspace connects chat, files, projects, agents, computers, and deployable resources.
   - Output: one generated report or small web page.

2. Create Your First Thread
   - Goal: show how a user gives work to an agent.
   - Demo flow: choose agent, choose computer, send prompt, inspect trace/logs, open generated files.
   - Key proof points: agent work is observable, not hidden.
   - Output: a short analysis document or task plan.

3. Understanding the Thread Screen
   - Goal: explain chat, trace, changes, log boxes, files, and run summary.
   - Demo flow: open a completed thread, expand tool logs, open file previews, inspect source changes.
   - Key proof points: users can audit what happened.
   - Output: user knows where to find results, logs, sources, and costs.

4. Search, Private Chat, and Navigation
   - Goal: show daily workspace ergonomics.
   - Demo flow: top nav search, file search, thread search, private chat toggle, account/notifications.
   - Key proof points: users can find previous work and work privately when needed.

5. Compute Tokens and Usage Basics
   - Goal: make cost transparent early.
   - Demo flow: left sidebar CT widget, settings usage, model table, skill model defaults.
   - Key proof points: costs are visible by agents, computers, resources, and skills.

### Series 2: Work Mode

Purpose: show the Create workspace as the daily operating system.

1. Files as Workspace Memory
   - Goal: explain filebases and why files are not just attachments.
   - Demo flow: upload files, create file, preview image/docx/pptx/csv/video, edit code, save changes.
   - Key proof points: agents can read and work with stored files.
   - Output: a prepared workspace with documents and assets.

2. Chat With Images and Files
   - Goal: show direct file and image conversations.
   - Demo flow: open image preview, ask about the image, start a thread with image attached, inspect image understanding log.
   - Key proof points: images are understood directly, not through expensive workarounds.
   - Output: image analysis or edited image.

3. Edit Images With Select and Crop
   - Goal: show inpaint-style workflows.
   - Demo flow: open image, use Select/lasso, paint region, prompt an edit, crop and save.
   - Key proof points: users can direct edits precisely.
   - Output: before/after image.

4. Projects: From Chat to Organized Work
   - Goal: show project workspace, backlog, board, tasks, and rules.
   - Demo flow: create project, generate tasks, open ticket details, comment with markdown, use board/backlog.
   - Key proof points: agent output can become structured work.
   - Output: populated project backlog.

5. Mission Control and Full Auto
   - Goal: show project-level automation.
   - Demo flow: run Mission Control on a project, inspect tasks, generated agents, thread outputs, project cost.
   - Key proof points: agents can coordinate project execution.
   - Output: tasks completed or ready for review.

6. Calendar and Scheduled Tasks
   - Goal: show recurring and one-time automations.
   - Demo flow: calendar page, create scheduled task, choose project/computer, show paywall for free users if relevant.
   - Key proof points: work can run without manual prompting.
   - Output: scheduled daily briefing or weekly report.

### Series 3: Configure

Purpose: show how users shape the agents and infrastructure behind the work.

1. Configure Your Workspace
   - Goal: explain Configure home, analytics, resources, and setup sections.
   - Demo flow: configure overview -> usage analytics -> resources list.
   - Key proof points: users can see and tune how the workspace runs.

2. Agents and Teams
   - Goal: create a useful agent and explain teams.
   - Demo flow: agent list, create agent, model selection, permissions, skills, team routing.
   - Key proof points: agents can be specialized for roles.
   - Output: one custom agent.

3. Computers and Filebases
   - Goal: explain computers as isolated work environments.
   - Demo flow: create computer, choose profile, open files for selected computer, switch from task input.
   - Key proof points: agents operate in selected computers with persistent files.
   - Output: computer with its own files.

4. Skills and Defaults
   - Goal: explain system skills and default model settings.
   - Demo flow: open skills, view source files, enable defaults, set image/video/research default models.
   - Key proof points: skills are inspectable and configurable.
   - Output: configured image/video/research defaults.

5. Plugins and Connectors
   - Goal: show connected apps.
   - Demo flow: GitHub/Google Drive/Gmail/Notion style connectors, browse connector files, attach sources.
   - Key proof points: agents can use external context.
   - Output: thread using connected source material.

6. Models and Pricing
   - Goal: explain model choice and CT costs.
   - Demo flow: Models page tabs: Agent Models, Image, Video, Deep Research.
   - Key proof points: users can compare quality, speed, cost, and default skill models.

### Series 4: Develop

Purpose: show the platform as an agent-native developer environment.

1. Developer Overview
   - Goal: explain Develop mode.
   - Demo flow: develop home, analytics, quickstart, API keys, resources.
   - Key proof points: the platform can host production-like resources.

2. Build and Deploy a Web App
   - Goal: generate and deploy a web app.
   - Demo flow: create web app, source files, deploy, logs, custom domain, open app.
   - Key proof points: agents can produce runnable web apps.
   - Output: deployed app.

3. Custom Domains for Web Apps
   - Goal: explain domain mapping and DNS verification.
   - Demo flow: add domain, DNS records, verify/check status, edit/remove domain.
   - Key proof points: deployed outputs can become public products.

4. Functions: Backend Logic From Agent Workspaces
   - Goal: build and invoke a function.
   - Demo flow: create function, source code, deploy, invoke function box, API key toggle, logs.
   - Key proof points: agents can deploy callable backend logic.
   - Output: deployed function with invocation example.

5. Databases and Data Browser
   - Goal: show managed data resources.
   - Demo flow: create database, collections, documents, fields, export JSON.
   - Key proof points: agents can read/write structured application data.
   - Output: sample database.

6. Auth, Secrets, and Secure Apps
   - Goal: show identity and secret management.
   - Demo flow: create auth users, create secrets, use secret in function/web app.
   - Key proof points: apps can manage users and credentials.
   - Output: authenticated mini app or function using a secret.

7. Payments With Stripe
   - Goal: show the payments module.
   - Demo flow: create payment resource, connect Stripe, inspect details and configuration.
   - Key proof points: monetizable app flows are possible.

8. Logs and Source Files
   - Goal: show how to debug deployed resources.
   - Demo flow: web app/function logs, filters, expanded log row, source files, file preview.
   - Key proof points: users can inspect production behavior.

### Series 5: Imagine

Purpose: show creative production with images, videos, and templates.

1. Imagine Overview
   - Goal: introduce templates, favorites, and generation.
   - Demo flow: Explore -> template details -> task input -> generated asset.
   - Key proof points: templates make creative generation repeatable.

2. Image Generation With Templates
   - Goal: show template-driven image generation.
   - Demo flow: choose template, set style/aspect/model, generate, open output.
   - Output: campaign image.

3. Video Generation
   - Goal: show Seedance/Grok video generation through Imagine.
   - Demo flow: choose video-capable template or prompt, model selector, generate, view video log box and file preview.
   - Output: short video.

4. Multi-Asset Templates
   - Goal: show pitch-deck/campaign workflows.
   - Demo flow: template with multiple images/videos, slider, select/deselect assets, generate directory output.
   - Key proof points: agents can use multiple references in one workflow.
   - Output: asset pack or pitch deck resources.

5. Create Your Own Template
   - Goal: show template creation.
   - Demo flow: create template, upload multiple images/videos, set default styles/aspect ratio/instructions.
   - Key proof points: users can preserve brand and visual direction.
   - Output: reusable custom template.

6. Image to Video
   - Goal: show cross-mode generation.
   - Demo flow: open image template, switch to video model, generate motion variation.
   - Key proof points: image and video workflows share one template system.

### Series 6: Use Case Playbooks

Purpose: show complete business outcomes.

1. Daily Briefing Automation
   - Build a scheduled morning briefing from web search, Gmail, files, and a project context.

2. Lead Generator Workspace

   - Run `/research`, include images, generate markdown report, preview and export it.

4. Campaign Asset Factory
   - Use Imagine templates to create ad images, short videos, and a pitch deck folder.

   - Upload docs, configure an agent, connect external files, and answer support questions.

6. Data Validation and Cleanup
   - Upload CSV/XLSX, inspect spreadsheet preview, ask agent to validate and create a report.

   - Use projects, tasks, files, calendar, and Mission Control to run a launch plan.

    - Upload image, crop, select region, prompt an edit, use the result in a new thread.

## Episode Format

Recommended structure for most videos:

1. Hook: show the finished output first.
2. Setup: show the exact page and input.
3. Run: let the agent work, but compress waiting time.
4. Inspect: open logs, files, tasks, or deployed output.
5. Explain: call out why this is different from ordinary chat.
6. Next step: point to a related workflow.

Keep most walkthroughs between 4 and 8 minutes. Keep teasers below 45 seconds.

- A "Lead Generator" project with tasks, files, and generated outputs.
- A few sample documents: PDF, DOCX, CSV/XLSX, PPTX, image, video.

- One deployed function with an invocation example.
- One database with collections and documents.
- One auth resource with sample users.

## Production Notes

- Avoid abstract demos. Every video should create or inspect a concrete artifact.
- Show the UI state before and after the agent run.
- Use real logs when possible, but collapse long traces.
- Mention compute tokens only when relevant to trust, cost, or model choice.
- Prefer examples that combine multiple platform areas, such as files plus projects, or Imagine plus threads.
- Keep sensitive data mocked: API keys, secrets, customer names, and billing details.
- For developer videos, include a final "open app", "invoke function", or "download/export" moment.

## Suggested Recording Order

1. Record the platform overview first.
2. Record the thread and files videos next because they explain the core UX.
3. Record Projects and Imagine after that because they show differentiated workflows.
4. Record Configure and Develop once demo resources are stable.
5. Record use case playbooks last, using material created in earlier videos.
